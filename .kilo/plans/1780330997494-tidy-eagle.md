# Plan: Enhance Inventory Slot Tooltips with Item Metadata

## Problem
Currently, when hovering over inventory slots, only the item ID is shown in the tooltip (e.g., "Item 5"). The user wants to display more meaningful metadata such as item name, flavor text, etc.

## Current Implementation
In `src/client/app/ui/inventoryPanel.ts`, line 187:
```typescript
slot.title = `Item ${item.itemId}`;
```

## Solution
Create a client-side item registry to load item definitions and use them to enrich tooltips with item name, flavor, and other metadata.

### Steps:
1. **Create Client Item Registry**
   - File: `src/client/app/items/itemRegistry.ts`
   - Load item definitions from `/src/db/data/items.json` (or public equivalent)
   - Provide `getItemDef(itemId)` function similar to server version

2. **Initialize Registry in App**
   - Modify `src/client/app/main.ts` to load item registry on app startup
   - Store registry in app context for access by UI components

3. **Update Inventory Panel**
   - Modify `src/client/app/ui/inventoryPanel.ts`
   - Import and use item registry to fetch item definitions
   - Enhance tooltip to show: `${itemDef.name}\n${itemDef.flavor || ''}`
   - Handle case where item definition is not found (fallback to current behavior)

### Implementation Details:
- Item definition structure from `src/shared/items/itemTypes.ts`:
  ```typescript
  export type ItemBaseDef = {
    id: ItemId;
    name: string;
    type: ItemType;
    stackSize: number;
    flavor?: string;
  };
  ```
- Tooltip format suggestion: 
  ```
  Item Name
  Flavor text (if available)
  ```
- Ensure graceful degradation if item definition loading fails

### Files to Modify/Create:
1. Create: `src/client/app/items/itemRegistry.ts`
2. Modify: `src/client/app/main.ts` (initialize registry)
3. Modify: `src/client/app/ui/inventoryPanel.ts` (enhance tooltips)

### Dependencies:
- None new; uses existing JSON import/fetch mechanism
- Leverages existing item definition structure

## Benefits:
- Clean separation of concerns (registry pattern)
- Reusable across other UI components that need item data
- Maintains existing functionality as fallback
- Follows existing patterns in codebase (similar to server item registry)
